---
title: 流量边界
description: 明确 Canis Minor 0.1 会截获、绕过或不支持哪些流量。
---

当前保证范围经过刻意收窄：Ubuntu 24.04 x86_64 上由主机发起的 IPv4 TCP 与 UDP。

## 会截获

- 普通主机进程创建的 IPv4 TCP 连接。
- 普通主机进程发送的 IPv4 UDP 数据报。
- `dockerd`、`containerd` 等主机守护进程的镜像拉取流量。
- TCP 与 UDP 目标端口 53：进入隧道后由服务端改写到 `dns_upstream`。

截获发生于 nftables `output` 路径。透明监听器恢复原始目标元数据，并通过 Yamux 子流发送带版本的请求。

## 明确绕过

规则绕过以下类别，以保留主机功能并防止循环：

- 回环与本地目标。
- IPv4 广播、多播与链路本地网段。
- DHCP 流量。
- 配置的隧道服务器连接。
- 入站连接所属的回复流量。
- 带配置中 bypass mark 的 Canis Minor 套接字。

单元测试覆盖生成规则，但运维者仍应在实际内核与 nftables 版本上验收检查。

## 保证范围之外

| 流量                         | 0.1 行为                                       |
| ---------------------------- | ---------------------------------------------- |
| 经主机转发的容器命名空间流量 | 不保证；通常走 `forward` 而不是主机 `output`。 |
| ICMP                         | 保持主机原有网络路径。                         |
| IPv6                         | 不截获、不进入隧道。                           |
| TCP/UDP 以外协议             | 保持不变。                                     |
| 到客户端主机的入站连接       | 不代理；其回复被有意绕过。                     |
| 多个同时在线客户端           | 不支持；新认证会话会替换旧会话。               |

## DNS 影响

所有进入隧道且目标端口为 53 的流量都会改写，无论原始 IPv4 地址是什么。这覆盖传统 UDP DNS 与 TCP 回退，但不覆盖 DNS-over-HTTPS、其他端口的 DNS-over-TLS、应用自带加密 DNS 或 IPv6 DNS。

修改 `dns_upstream` 只改变这些隧道查询的目标，不会配置 `/etc/resolv.conf`、systemd-resolved、浏览器安全 DNS 或容器命名空间 DNS。

## 围绕边界设计策略

Canis Minor 不是完整主机防火墙。若组织策略要求阻止直连、IPv6、私网可达、加密 DNS 或容器流量，应独立实施这些要求。必须同时验证隧道在线与离线状态，因为 fail-open 恢复会有意还原原始直连路径。
